s04 学习地图:Hooks(挂载式扩展)
1. 先搞清楚:这一章在讲什么
要解决的问题:s03 加权限检查、s04 还要加日志、自动 git add、通知……每加一个功能都要改 agent_loop 函数本体,循环很快膨胀成一锅粥。
解决方案:把循环变成稳定的核心,扩展逻辑挂在外面。具体是三个东西:
HOOKS 注册表:事件名 → 回调列表的字典;
register_hook(event, callback):加扩展 = 注册一个回调,循环一行都不用改;
trigger_hooks(event, *args):循环在关键节点调它,由注册表决定跑什么。
核心思想:"你想扩展的是 Agent 的行为,但你改的却是循环本身"——循环应该是稳定的,扩展应该挂在外面。

4. 必须理解透的四个机制
返回值约定 + 短路:None = 放行/继续,非 None = 拦截(PreToolUse)或强制续跑(Stop)。trigger_hooks 遇到第一个非 None 就返回,后面的 hook 不再执行。这是教学版的极简设计——CC 的 HookResult 有 14 个字段,教学版收敛成一个返回值。

注册顺序 = 执行顺序,而且敏感:permission_hook 必须注册在 log_hook 前面。如果反过来,被拦截的调用也会先被记录(日志失真),更糟的是如果前面的 hook 先返回非 None,后面的权限检查根本没机会跑。想清楚"同一个事件挂多个 hook 时,顺序意味着什么"是这章最重要的心智模型之一。

Stop hook 的 force 续跑:stop_reason != "tool_use" 时先触发 Stop hook,如果返回字符串,就以 user 消息注入并 continue——hook 可以阻止循环退出。教学版注释里明确提醒:返回 None = 允许退出,返回字符串 = 强制续跑。想想看:如果一个 Stop hook 永远返回字符串,会发生什么?(无限循环——CC 用 stopHookActive 防这个,见下)

职责的第二次上移:s03 把安全从工具内部搬到权限层,s04 把权限从循环硬编码搬到 hook 扩展点。两次上移的方向一致:把稳定核心和可扩展逻辑分离。s05 的 nag reminder、s06 的 subagent、s07 的 skill 加载……后面所有章节的机制都是通过注册 hook 或新工具接入的,循环本身几乎不再变。

6. 进阶对照(README 附录,必读)
CC 有 27 个 hook 事件,教学版只讲 4 个:工具类(Pre/PostToolUse、PostToolUseFailure)、会话类(SessionStart/End、Stop)、用户交互(UserPromptSubmit、PermissionRequest、PermissionDenied)、子 Agent、压缩(PreCompact/PostCompact)、团队(TeammateIdle、TaskCreated)……其余 23 个都是同样的模式;
HookResult 有 14 个字段:permissionBehavior(allow/deny/ask/passthrough)、updatedInput(改工具输入)、additionalContext(附加上下文)、preventContinuation(优雅停机)、blockingError(注入对话让模型自纠)等;
关键安全不变式:hook 返回 allow 不能绕过 settings.json 的 deny/ask 规则——教学版没有这层,所以它的"非 None 即拦截"在生产环境会有漏洞;
stopHookActive:防止 Stop hook 报错 → 模型自纠 → 再报错 → 再自纠的无限循环;
hook_stopped_continuation:PostToolUse 返回 preventContinuation: true 时优雅停机,不是崩溃,是"完成"。

【修订版(基于最新 s04 代码)】
Q1: 四个 hook 的触发时机?
A: UserPromptSubmit = 用户输入提交后、进入 LLM 前;PreToolUse = 工具执行前;PostToolUse = 工具执行后;Stop = 循环即将退出时(stop_reason != "tool_use")。覆盖完整 agent cycle = 输入进入 → 执行前 → 执行后 → 退出,一个 query 的生命周期全部包住。
原回答错在哪:"返回结果"不对——结果打印是 agent_loop 返回后 main() 里做的,Stop 是退出前最后一个 hook。

Q2: trigger_hooks 的返回值约定?
A: None = 放行/继续;非 None = 有干预。PreToolUse 非 None = 拦截本次工具执行,该值作为 tool_result 回填给模型(原因);Stop 非 None = 强制续跑(force continuation),该值作为 user 消息注入,循环 continue 不退出。
原回答错在哪:"Stop对话总结"不对——summary_hook 打印总结是因为它 return None 且打印是副作用,非 None 的含义是强制续跑。代码里 257/287 行的注释已写对。

Q3: 同一个事件挂多个 hook,执行顺序?
A: 注册顺序 = 执行顺序;当前 trigger_hooks 是短路版,第一个非 None 直接返回,后面的 hook 不再执行。log_hook 注册在 permission_hook 前面 → 被拦截的调用也会先打印 [HOOK] 日志(日志失真)。
备注:曾把 trigger_hooks 改成"全部执行、最后一个非 None 生效",又回退成原版短路。两种语义:短路 = 第一个非 None 生效;全部执行 = 最后一个非 None 生效。当前代码是短路版。

Q4: s03→s04 权限检查的变化?
A: check_permission() 从循环体硬编码 → 变成 PreToolUse hook(permission_hook);且现在 permission_hook 只是薄壳,规则回到数据表 PERMISSION_RULES(hook 管挂载点、数据管规则)。职责上移的延续 = 循环保持稳定:s02→s03 把安全从工具内部(safe_path)移到权限层,s03→s04 把权限从循环硬编码移到 hook 扩展点,循环零改动。

Q5: 教学版 vs HookResult 的差距?
A: 教学版一个返回值走天下(None/非 None);CC 的 HookResult 有 14 个字段、多种意图:permissionBehavior(allow/deny/ask/passthrough)、updatedInput(改参数)、additionalContext(加上下文)、preventContinuation(优雅停机)、blockingError(注入消息让模型自纠)。
为什么 hook allow 不能绕过 deny/ask:settings.json 里的 deny/ask 是用户的策略,优先级高于 hook;hook 是可执行脚本,可能写错、可能被恶意利用,若 allow 能绕过 deny 就成了安全后门。规则:策略 > hook,hook 只能更严格,不能放宽。教学版没有 settings 层,所以不存在这个不变式——这是教学版在安全上的简化。

Q6: Stop hook force 续跑的风险?
A: 无限自纠循环(模型自纠 → hook 再次 block → 注入消息 → 再自纠 → ...)。CC 解法:stopHookActive 标志,第一次 block 后循环带标志重入,hook 收到标志不再 block。s04 实现:force 只在第一次生效(force and not stop_hook_active),第二次 stop 时 hook 仍执行(能收到标志)但循环不认 force,直接退出。
