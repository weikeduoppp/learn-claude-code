## 【修订版(基于最新 s09 代码)】

Q1: 四个子系统及时机?
A: 四个子系统 = 存储、加载、写入、整理。
- 存储:每个记忆一个 .md 文件(YAML frontmatter:name/description/type)+ MEMORY.md 索引。写新记忆时触发(文件落盘 + _rebuild_index 重建索引)。
- 加载:每轮用户请求开始时。索引注入 SYSTEM(build_system,常驻,可被 prompt cache 缓存);内容按需注入当前 user turn(load_memories → LLM side-query 选 ≤5 个文件,读全文注入)。
- 写入:每轮结束、模型停止且没有 tool_use 时触发(extract_memories)。
- 整理:文件数达到阈值时触发(consolidate_memories)。

原回答哪不对:"system prompt"严格说是索引的注入位置(加载路径一),不是存储本身。存储 = 文件 + 索引。另外阈值:README 默认 10,但当前代码 CONSOLIDATE_THRESHOLD 已改成 2(未提交改动),所以"攒够 10 或指定数量"= 可配置阈值,当前生效值是 2。

Q2: 为什么用 LLM 选记忆而不是 embedding?降级路径?
A: 记忆库规模小(CC 最多 200 条,每次只选 ≤5 条),专门上 embedding/向量库不划算;而且选记忆需要理解语义和上下文("这条描述和当前任务有关吗"),LLM side-query 直接能干,还能保守处理——"不确定就不要选"。降级路径:side-query 失败(API 错误、JSON 解析失败)时,回退到关键词匹配 name + description(select_relevant_memories 里的 fallback 分支)。

Q3: 两条加载路径注入哪里?为什么内容注入要拷贝 request_messages?
A: 索引 → SYSTEM prompt(每轮开头读 MEMORY.md);内容 → 当前 user turn,拼在用户消息内容前面,包在 <relevant_memories> 里。
为什么用 request_messages 拷贝:不污染 messages 本体。messages 之后还要走压缩管线(snip/micro/compact)、写 transcript、并在本轮结束时被 extract_memories 提取;如果直接改 messages,注入的记忆会被算进上下文预算、被压缩,还可能被当成对话细节重复提取成记忆(自污染)。拷贝只影响这一次 API 请求,对历史零影响。

Q4: 为什么提取用 pre_compress 快照?
A: 压缩有损,细节会丢("用 tab 缩进"可能被简化成"用户有代码风格偏好")。pre_compress 是每轮 while 循环开头、压缩管线执行之前拍的原始 messages 快照,提取器从原始对话里挖偏好,保真度最高。

Q5: 怎么防重复写入?怎么防无限膨胀?
A: 防重复:提取 prompt 把已有记忆清单(existing_desc)喂给 LLM,要求"如果已被现有记忆覆盖就返回 []";CC 还有重叠保护(主 Agent 已写入则跳过提取)。
防膨胀:整理时 LLM 去重合并、淘汰过时/矛盾记忆,并明确要求"Keep the total under 30 memories";CC 侧另有硬预算——每文件 ≤200 行/4096 字节、MEMORY.md 索引 ≤200 行/25KB、单 session 注入 ≤60KB。

Q6: Dream 为什么必须低频?CC 四层门控 vs 教学版阈值?
A: 必须低频,因为合并是重操作(LLM 调用 + 扫描 + 重写文件),太频繁浪费;而且整理需要攒够足够的新信号才有意义,否则合并出来的东西和原来差不多。
CC 四层门控(autoDream.ts):① 时间门控(距上次 ≥24h);② 扫描节流(避免频繁扫盘);③ 会话门控(自上次合并以来修改了 ≥5 个 transcript);④ 锁门控(.consolidate-lock 文件,防多进程并发;锁 1 小时自动过期,用于崩溃恢复)。
教学版:文件数阈值,README 默认 10,当前代码已改成 2;整理后总数压到 30 以下。

Q7: User Memory vs Session Memory?sessionMemoryCompact?
A: User Memory 管跨会话长期知识:memory/ 下多个 .md 文件,加载到 system prompt;Session Memory 管单会话内跨 compact 的连续性:session-memory/<id>/memory.md,加载到 compact 摘要。
sessionMemoryCompact:autoCompact 之前先读 session memory 文件,如果内容足够(≥10K token、≥5 条文本消息、≤40K token),就直接拿 session memory 当摘要,不调 LLM;不够才走完整 LLM 压缩。
