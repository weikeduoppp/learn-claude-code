# 学习地图

## s11 到 s12

`s11` 解决的是“请求失败了怎么办”。

`s12` 解决的是“任务太大、太长、跨会话时，进度怎么管理”。

一句话记住：

> `s11` 管调用韧性，`s12` 管任务持久化。

再压成一句：

> 从“这一轮调用别崩”，进入“整个任务系统怎么跨轮、跨会话继续”。

## 这章最该记住的 6 句话

1. `s12` 解决的是任务管理，不是错误恢复。
2. `todo_write` 是会话内步骤列表，`task system` 是跨会话任务系统。
3. 任务是否可开始，不由模型感觉决定，而由依赖是否完成决定。
4. `claim` 和 `complete` 是动作，`pending / in_progress / completed` 是状态。
5. `.tasks/*.json` 让 agent 可以在下次启动时恢复任务进度。
6. `s12` 的本质是：把任务从“当前脑内清单”升级成“可持久化、可依赖、可恢复的任务图”。

- 重启程序后，`list_tasks` 仍能看到之前的任务

建议实验顺序：

1. 创建一组有依赖的任务：schema -> endpoints -> tests
2. 先尝试直接 claim `tests`，观察为什么会被拒绝
3. 按顺序完成上游任务，观察解锁链条
4. 退出程序后重新启动，再 `list_tasks`

## 当前理解框架

- `Task`：任务对象
- `.tasks/`：持久化存储
- `blockedBy`：依赖边
