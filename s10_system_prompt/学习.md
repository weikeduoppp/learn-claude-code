3. `PROMPT_SECTIONS`、`assemble_system_prompt()`、`get_system_prompt()` 分别负责什么？
 `PROMPT_SECTIONS`、 声明sections 内置identity
 `assemble_system_prompt()`、 将identity, tool, workspace, memory组装prompt
 `get_system_prompt()` 获取prompt, 识别prompt context是否有变动, 没变动使用缓存, 有的话使用新的prompt
可以更工程化一点。
更标准的分工是：
PROMPT_SECTIONS：定义 prompt 片段，负责“拆段”
assemble_system_prompt()：根据 context 选择并拼接 section，负责“组装”
get_system_prompt()：根据 context key 做缓存，负责“复用”
PROMPT_SECTIONS 负责定义，assemble_system_prompt() 负责选择和拼接，get_system_prompt() 负责缓存。
 
4. 为什么 `memory section` 要按真实状态加载，而不是按消息关键词猜？memory按需加载, 有索引内容就加载, 没有就不加载, cache容易命中, token消耗少
memory section 要按真实状态加载，不只是因为“有就加载、没有就不加载”，而是因为：
prompt 组装应该依赖系统真实状态，而不是依赖模型消息里的文本猜测。
如果靠关键词猜，比如用户说了 “remember” 或 “memory”，并不代表真的有 .memory/MEMORY.md 文件；反过来，文件存在但用户没提关键词，也仍然应该加载。
所以这题的关键答案是：
真实状态比关键词更可靠，prompt 组装应该基于真实可验证状态。
